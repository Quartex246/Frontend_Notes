在之前的学习中，元素永远都会像写文档一样从上到下依次排列，布局方式相当单一：块元素各占一行，行内元素只能顺着文字排。如果想让两个盒子左右并排、或者把某个元素靠左/靠右摆放，就要用到**浮动（float）**。浮动的作用是让元素**脱离标准流（文档流）**，从而可以按照开发者的想法移动到指定位置。

> 浮动最初是为“文字环绕图片”设计的，后来才被大量用于页面布局。现在多列布局更推荐 Flex/Grid，但浮动仍然是必须理解的基础。

## 浮动和行内块的区别

行内块元素和浮动元素都能“一行排放、还能设置宽高”，但两者并不一样：

- **缝隙**：多个 `inline-block` 元素之间，HTML 源码里的换行和空格会被渲染成一个空白字符，元素之间出现缝隙；浮动元素紧贴在一起，没有这种缝隙。

- **方向**：行内块默认只能从左往右排，想靠右要借助 `text-align` 等外层属性；浮动可以直接用 `float: left` / `float: right` 指定贴哪一边。

- **对齐**：行内块受 `vertical-align` 和基线影响，容易出现底部对不齐；浮动元素默认顶部对齐。

- **文档流**：行内块仍然占据标准流的位置，浮动元素则完全脱标。

所以可以粗略理解为：**浮动元素 = 脱标 + 具备行内块的部分特性 + 可指定左右方向**。

浮动是相对于它的**包含块**（通常就是父元素的内容区）来定位的：`float: left` 贴着父元素左边，`float: right` 贴着父元素右边。

## 三大特性

### 1. 脱标

脱离标准流，可以移动到指定位置。或者说，相比于其他元素，脱标的元素会**浮在其他元素之上**，后面的标准流元素会认为它不存在，直接占据它原来的位置。

注意：脱标不等于“什么都影响不到”。浮动元素仍然会影响后面**行内内容**的排布，这正是文字环绕效果的来源。

### 2. 一行显示，顶部对齐

多个浮动元素同时设置时，会按照属性值排成一行，并**顶端对齐**。也就是说，它会像一个字一样一直往后排；一行放不下时自动换行。

- 多个 `float: left`：从左往右依次排列，放不下就换到下一行；
- 多个 `float: right`：从右往左依次排列，放不下同样换行。

### 3. 有行内块特性

浮动元素可以设置宽高、内外边距，也不会独占一行。并且按照 CSS 规范，元素一旦浮动，它的 `display` 计算值会变成 `block`——所以像 `span`、`a` 这样的行内元素，加上浮动后也能设置宽高。

行内块和 `display` 的细节可以回看 [[3. 属性]]。

## 举例子和解释说明

接下来我们看一段实际的代码：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>浮动示例</title>
  <style>
    .father {
      background-color: aquamarine;
      border: 3px solid brown;
      /* 先不设置高度，观察父元素会不会被子元素撑开 */
    }

    .left-son,
    .right-son {
      width: 100px;
      height: 100px;
    }

    .left-son {
      background-color: yellowgreen;
      float: left;
    }

    .right-son {
      background-color: yellow;
      float: right;
    }
  </style>
</head>

<body>
  <div class="father">
    <div class="left-son">左浮动</div>
    <div class="right-son">右浮动</div>
  </div>
</body>
</html>
```

可以看到，左浮动元素贴着父元素左边，右浮动元素贴着父元素右边，两者都脱离了标准流，并被限制在同一个父元素的内容区里。

### 复制多个元素

同向浮动的元素会沿着该方向继续排列，父元素宽度不够时自动换行；多个右浮动元素则是从右往左排。下面的截图就是把左右浮动各复制了几份后的效果：

![[Pasted image 20261031201851.png]]

绿色左浮动从左往右铺满一行后换行，黄色右浮动从右往左排列。因为左浮动贴左边、右浮动贴右边，两拨元素各行其道，所以第二行中间会留出空档——浮动并不会自动把缝隙填满。多个高度不同的浮动元素换行时，还可能出现“卡位”导致排列参差不齐，这也是浮动布局容易出问题的地方。

## 坍塌和溢出

刚才提到，浮动这件事是相对于父元素和子元素的。默认情况下，父元素的高度是由子元素撑起来的——子元素有多高，父元素就跟着多高：

![[collapse1.png]]

但如果子元素应用了浮动，情况就变了。我们在上文已经说过，浮动元素对标准流元素来说是浮在表面上的，它不再占据原来的位置，也就**不再撑开父元素**。父元素失去支撑后，高度会变成 0（或者只剩没浮动子元素的高度），这就是**高度坍塌**。

![[collapse2.png]]

坍塌带来的后果是：父元素变成一条“线”甚至完全没有高度，原来在它下面的兄弟元素会向上填补这块空间；而浮动子元素还浮在上层，就会**溢出父元素的范围，盖在后面的兄弟元素上面**，导致页面错乱。图中绿色的浮动盒子已经明显跑到了父元素红框的外面，压住了下面的蓝色兄弟元素。

当然，也可以给父元素写死一个固定高度来避免坍塌，但实际开发中高度往往是不固定的——比如手机和电脑上内容高度可能不一致，写死高度很容易导致内容溢出。这时候就需要**清除浮动**了。

## 清除浮动

“清除浮动”不是把子元素的 `float` 取消，而是**让父元素重新包住浮动的子元素**，消除高度坍塌带来的影响。常用的有以下几种方法。

### 1. 额外标签法（隔墙法）

在浮动元素的最后面添加一个空的块级标签，给它设置 `clear`：

```html
<div class="father">
  <div class="left-son">左浮动</div>
  <div class="right-son">右浮动</div>
  <div class="clear"></div>
</div>
```

```css
.clear {
  clear: both;
}
```

`clear: left | right | both` 表示该元素的哪一侧不允许出现浮动元素。`both` 表示两侧都不允许，因此这个空标签会被“推”到所有浮动元素的下方，把父元素重新撑开。

缺点：增加了一个没有语义的空标签，结构不够干净，一般不推荐。

### 2. 父元素 overflow

给父元素设置：

```css
.father {
  overflow: hidden; /* 或 auto */
}
```

当 `overflow` 取 `hidden`、`auto` 或 `scroll` 时，父元素会创建 BFC（块级格式化上下文），BFC 在计算高度时会包含内部的浮动元素，于是父元素重新被撑开。

缺点：`hidden` 会把超出父元素的内容裁掉，像下拉菜单、阴影、定位元素等都可能被切；`auto` 则可能出现滚动条。使用时要注意场景。

### 3. 伪元素法（clearfix，推荐）

用 `::after` 在父元素内部末尾“造”一个看不见的块级元素来清除浮动，既不用改 HTML 结构，也不会裁剪内容：

```css
.clearfix::after {
  content: "";
  display: block;
  clear: both;
}
```

然后给父元素加上 `clearfix` 类：

```html
<div class="father clearfix">
  ...
</div>
```

这是最常用、兼容性也好的方案。可以把它写进公共样式，哪个父元素需要清除浮动就加哪个类。

### 4. display: flow-root（现代写法）

```css
.father {
  display: flow-root;
}
```

`flow-root` 会让父元素建立一个 BFC，但不会像 `overflow: hidden` 那样裁剪内容，是现在比较优雅的清除浮动方式。缺点是对非常老的浏览器不兼容（现代浏览器都已支持）。

### clear 属性小结

| 取值 | 含义 |
| --- | --- |
| `clear: left` | 左侧不允许有浮动元素 |
| `clear: right` | 右侧不允许有浮动元素 |
| `clear: both` | 两侧都不允许有浮动元素（最常用） |
| `clear: none` | 默认值，允许两侧有浮动 |

注意：`clear` 要写在**需要避开浮动元素的那个元素**上，而不是浮动元素自己身上。

## 浮动的典型用途和注意事项

- **文字环绕图片**：这是浮动的“本职工作”。给图片设置 `float: left`，后面的段落文字就会绕着图片排列：
  ```css
  img {
    float: left;
    margin: 0 12px 8px 0;
  }
  ```
- **多列布局**：早期常用“浮动 + 宽度百分比”做多列，现在更推荐 Flex/Grid；浮动布局主要用于兼容旧代码或文字环绕。
- 浮动元素虽然脱标，但它的 `margin`、`padding`、`border` 仍然有效，且浮动元素之间的外边距**不会合并**。
- 没有 `float: center`。想让浮动元素居中，通常要配合父元素宽度和 `margin` 计算，比较麻烦——这也是现在少用浮动做布局的原因之一。
- 多个高度不同的浮动元素换行时，可能出现“卡位”导致排列参差；可以在每组后面插入 `clear: both` 的元素强制换行。
- 浮动元素默认顶部对齐，不受 `vertical-align` 影响。

## 总结

- 浮动让元素**脱离标准流**，靠 `float: left / right` 贴向父元素的左右两侧；
- 多个浮动元素一行排列、顶部对齐、放不下自动换行，并且可以设置宽高；
- 浮动子元素不再撑开父元素，会造成**高度坍塌**，进而导致后面的元素上移、页面错乱；
- 清除浮动的常用方案：额外标签法、`overflow: hidden/auto`、伪元素 `clearfix`、`display: flow-root`；
- 现代布局优先用 Flex/Grid，浮动更多用于文字环绕和兼容旧代码。
